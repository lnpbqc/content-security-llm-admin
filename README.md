# Content Security LLM 中文管理端

独立的 Vue 3 + TypeScript + Vite + Vue Router + Element Plus 前端，连接 `content-security-llm` 的现有 FastAPI 接口。项目不包含 Python 后端、数据库迁移或模拟业务数据。

## 启动

要求 Node.js 22.18+ 或 24.12+，以及 pnpm。先按后端仓库 README 启动 FastAPI，再在本目录运行：

```powershell
pnpm install
Copy-Item .env.example .env.local
pnpm dev
```

访问 Vite 输出的本地地址。开发服务器将 `/api` 代理到 `VITE_DEV_PROXY_TARGET`，并将仅用于顶部连通状态的 `/__api_health` 改写为模型服务的 `GET /`。默认目标是 `http://127.0.0.1:8001`。业务后端仍在 8000；管理端只访问模型服务，不直连业务后端。

`.env.example` 中的 `VITE_API_BASE_URL` 默认为空，此时 API 请求走同源代理。若填入完整的模型服务源地址，例如 `http://127.0.0.1:8001`，请求将直接发往该地址；跨源访问须由部署环境允许 CORS。生产环境建议同源部署并把 `/api` 和 `/__api_health` 反向代理至模型服务，其中后者改写为 `/`。不要将任何凭据写入环境变量；`VITE_` 变量会进入浏览器构建产物。模型服务自己的 `business_api_base_url` 由其服务端配置管理，与本管理端代理和治理 MySQL 配置不同。

```powershell
pnpm test
pnpm type-check
pnpm build
pnpm preview
```

## Linux 一键启动

服务器需要安装满足上述版本要求的 Node.js 和 pnpm，模型服务需单独启动。上传或拉取项目源码及 `pnpm-lock.yaml`，不要复制 Windows 的 `node_modules`。

```bash
# 在项目目录执行；8080 可替换为你要暴露的端口
PORT=8080 bash start-admin.sh start

bash start-admin.sh status
bash start-admin.sh log          # Ctrl+C 退出日志，不停止服务
bash start-admin.sh stop
PORT=8080 bash start-admin.sh restart
PORT=8080 bash start-admin.sh fg # 前台运行，Ctrl+C 停止
```

不传命令时默认 `start`，不设置 `PORT` 时默认 `5173`。首次启动自动执行 `pnpm install --frozen-lockfile --prod=false`；每次启动都会执行 `pnpm build`，然后通过 Vite preview 监听 `0.0.0.0`，可访问 `http://服务器IP:端口`。端口被占用时启动失败，不会自动换端口。服务器防火墙或安全组需要放行所选 TCP 端口。PID 与日志保存在 `.admin/`，退出 SSH 后服务继续运行；服务器重启后需要重新执行启动命令。

预览服务沿用当前 `/api` 和 `/__api_health` 代理，模型服务默认地址为 `http://127.0.0.1:8001`。若模型服务在其他地址，可以这样启动：

```bash
PORT=8080 VITE_DEV_PROXY_TARGET=http://模型服务IP:8001 bash start-admin.sh start
```

也可将目标地址写入 `.env.local`；`VITE_API_BASE_URL` 保持为空即可走同源代理。重启时需再次传入自定义环境变量，或提前在当前 shell 中 `export`。这里使用 Vite 的预览服务提供构建后的页面，适用于简单部署；Vite 官方未将 preview 定位为正式生产服务器。

如果上传后出现 `\r` 或 `^M` 相关错误，先执行 `sed -i 's/\r$//' start-admin.sh`。也可执行 `chmod +x start-admin.sh` 后使用 `PORT=8080 ./start-admin.sh start`。

## 操作与接口范围

- 右上角“会话凭据”分别录入 Bearer 访问令牌与管理员密钥。两者仅存于当前标签页的 `sessionStorage`，可分别清除。令牌创建后的原文只在当次成功界面展示。
- “访问令牌”使用管理员密钥创建、查询、补充旧标签、修改状态和删除。可从模型服务查询业务用户，选择启用账号，为其创建标签为 `business-user:<业务 ID>` 的独立模型令牌；账号停用不自动禁用已有模型令牌，同一用户也可持有多枚。手动创建仍可填写自定义标签。单枚令牌在列表行中按 ID 启停或删除并需确认；批量修改也会二次确认。删除是不可恢复的软删除：令牌立即失效并从列表消失，历史调用归属保留。
- “模型配置”查询使用 Bearer 令牌；新增、编辑和删除同时发送 Bearer 与管理员密钥。编辑时 API Key 留空表示不更新；删除为后端软删除。
- “治理任务配置”使用管理员密钥保存三类模型绑定和业务 MySQL 连接。保存配置不会测试 MySQL 连通性。服务可在没有业务库时启动，但 worker 执行任务会失败。
- “通用模型调用”从接口获取输出类型；调用记录可切换当前令牌和管理员跨令牌视图，不展示令牌哈希或原文。
- “模型训练”从服务端获取默认参数、支持选项和两类 Python 示例。可填写业务数据集和版本、训练参数、可信 PyTorch 源码与张量契约，通过高级 JSON 配置优化器、调度器、损失、指标和自定义参数。创建需要同时录入 Bearer 与管理员密钥；查询、取消、增量指标和产物下载使用当前 Bearer。等待中、训练中和取消中每 3 秒轮询，终态停止；指标支持按游标继续加载。产物以文件流下载，不将令牌放入 URL。
- 训练页另支持“登记脚本”：从服务器目录选择入口后自动填入默认值。当前 CIFAR-100 脚本提供中文参数表单，说明数据下载、训练样本、学习率和服务器运行设备；高级输入/参数 JSON 与表单同步，也可查看完整字段定义。切换脚本会重置为所选脚本默认值。不会发送源码训练的业务数据集或张量字段。日志与指标是脚本自动上报的运行结果，无需作为创建参数填写；任意指标按实际键名展示，未上报进度不会补成百分比。两种任务均可按服务端返回的字节游标增量读取日志；单行过长时可提高每次读取预算后手动重试。
- “神经因果溯源”使用 Bearer 从服务端审核案例建单，按 limit/offset 分页查询当前令牌历史。每 3 秒轮询等待/运行中的任务，完成或失败后停止；仅成功后读取结果。文档干预、逐层 CRS、激活观测差异、组件 CRS 与实际回答分别展示，并保留模型环境、输入哈希和干预范围。CRS 不裁剪为 0–100%，激活差异不当作因果贡献。页面不下载模型、不启动或控制 GPU worker。
- “场景分析”支持接口提供的六种场景、正文与补充材料；跨文化场景可指定目标语种。“模型治理”先生成再治理并保留原始回答。“推理与全链路审计”提交可观测步骤、证据、规则和对象版本，展示模型建议及引用，不代表业务已核验。结构化材料使用 JSON 数组填写，提交前检查格式、长度和引用。
- “分析记录”可按类型、场景和状态分页筛选或按 ID 查询；失败分析仍可查看保存的原始生成内容与关联调用。切换 Bearer 后清理旧分析及训练详情，并忽略尚未结束的旧请求响应。
- 三类治理工作区可提交验证任务、按 ID 查状态、查看只读结果。价值任务支持按完整范围列出；异常和风险没有任务列表接口，只保留本会话最近提交的 ID。`pending` 与 `running` 每 3 秒轮询；失败任务只有掌握原提交参数时才可“按原参数新建”。页面不控制独立 worker。
- 结果查询使用完整的 `dataset_id`、`version_id`、`language`、`scheme_id`。价值页可看最新结果、指定 ID 和分页样本筛选；异常与风险另有历史结果和样本详情。候选字段变更只读，风险正文展示后端返回的已遮蔽内容。所有结果 GET 均不触发模型调用。
- 三类治理工作区从接口加载方案及当前令牌概览，仍需手动填写业务数据集与版本。风险结果支持按当前关键词、等级和状态导出全部匹配样本 JSON，并在样本详情中检索快照规则。配置页可测试已保存 MySQL 连接、治理表结构及读取权限；测试不保存正在编辑的表单。

## 目录

```text
src/
  api/                 两种响应格式与按接口分类的请求
  types/               后端业务类型
  stores/              当前会话凭据
  utils/               表单校验与任务轮询
  components/          范围输入和任务状态
  views/               令牌、模型、配置、调用、记录及三类治理工作区
  __tests__/           API 适配、轮询和关键表单测试
```

## 与后端代码核对的细节

- `POST /api/auth/token` 不返回令牌原文、ID 或标签；原文必须由前端暂存并仅在本次成功操作中显示，ID 和标签从管理员列表取得。
- `GET /api/v1/admin/business-users` 用管理员密钥从模型服务获取分页业务用户；管理端不获取业务登录令牌。返回的 `enabled` 只控制用户是否可在授权弹窗中被选择，不改变既有模型令牌状态。
- 价值和异常任务响应的 ID 字段为 `task_id`，风险任务为 `id`。价值任务列表要求 `kind` 和完整四元组；异常、风险没有列表接口。
- 业务库 GET 只返回连接元数据和 `password_configured`，重新保存时必须重新输入密码；旧 `settings.local.json` 的治理字段并非当前配置来源。
- `/api` 成功时直接返回对象或数组，DELETE 返回 204；`/api/v1` 的业务值在 `data` 中，失败消息与 `trace_id` 一并展示。
- 更换 Bearer 令牌后查询原任务或结果可能得到 404，这是按令牌隔离的正常边界。管理端不提供业务数据集目录、人工复核、候选变更应用、修改集发布或资源目录；这些业务写操作仍由原业务后端处理。
- 旧模型配置、通用调用与调用记录继续使用 `/api` 裸响应接口，保留原来的输入长度和执行配置；新增训练、分析和治理能力使用 `/api/v1` 包裹响应。
